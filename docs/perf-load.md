# 성능·부하 기록

## 측정 1 — 로컬 서버, 교실 30명 시뮬레이션 (2026-10-27)

- 도구: `node scripts/load/classroom.mjs --vus 30 --seconds 120` (기본 생각 시간 4초, 실행 한 번에 40% 확률로 AI 도우미 질문)
- 대상: `next start`(프로덕션 빌드), Supabase·Claude 미연결 → 체험 모드 API(서버 시뮬레이션·서버 채점·규칙 기반 튜터)
- 학생마다 다른 IP 헤더로 속도 제한을 학생 단위로 적용

| 엔드포인트 | 요청 | 오류율 | 속도 제한(429) | p50 | p95 |
|---|---|---|---|---|---|
| `/api/demo/run` (서버 시뮬레이션) | 900 | 0% | 0 | 4 ms | 8 ms |
| `/api/demo/check` (서버 채점) | 900 | 0% | 0 | 3 ms | 7 ms |
| `/api/tutor` (규칙 기반) | 359 | 0% | 0 | 4 ms | 10 ms |

해석: 시뮬레이션·채점은 순수 계산이라 서버 부담이 매우 작다. **실제 병목은 Claude 응답 시간과 Supabase 왕복**이므로 아래 스테이징 측정이 필요하다.
참고: 생각 시간 1.5초·매 실행마다 질문(비현실적 과부하)으로 돌리면 체험 모드 튜터 속도 제한(학생당 분당 15회)이 62% 요청을 막았다 — 의도된 보호 동작.
